# Agent Note: 浏览器会话模拟登录

Status: implemented

[English](2026-09-12-browser-session-mock-login.md) | 中文

## 问题

在正式身份服务及其授权协议尚未存在时，Web 应用需要在主工作区前提供一个入口步骤。如果表单声称能保护服务端资源，却把完整工作区挂载在未实现表单的后面，这一视觉流程就会产生误导。

## 决策

root 布局持有本地化的模拟登录，在其成功前不挂载三栏应用框架。表单在去除首尾空白后只接受精确的用户名 `simon`，并接受每一种密码，包括空值。成功状态保存在 `sessionStorage` 中，因此它可以跨同一浏览器标签页的刷新存活，但不会变成跨标签页或持久身份。

浏览器测试脚手架可以通过 `#dsh-mock-login=simon` fragment 请求同一个公开的模拟身份。登录门在挂载应用前消费并移除该 fragment，使无关的浏览器场景能够专注于其所属行为，而不会添加另一种身份验证机制。

页面将自身标识为演示身份验证，并说明正式身份服务待接入。组件约定与包文档都明确说明它不提供服务端身份验证或授权。替换它需要经服务端验证的会话以及应用启动决策；正式凭据绝不属于该组件。

## 考虑过的替代方案

**把模拟登录保存在持久设置或 local storage 中。** 不采用，因为占位流程不应像持久账户会话，也不应在标签页之间泄漏。标签页作用域的存储使其有限生命周期保持明确。

**在表单后挂载应用，再用 CSS 隐藏。** 不采用，因为隐藏的控件与 effect 仍会在登录前运行，并可能发起请求。条件挂载为占位流程提供了清晰的生命周期边界。

**实现一枚假服务端 token。** 不采用，因为它会新建第二套临时身份验证协议和迁移负担，却无法提供真实身份保证。

## 结果

- 每个新浏览器标签页都从登录页开始；`simon` 可以用任意密码进入。
- root React 框架下方代表的应用服务在模拟登录成功前不会挂载，Host 服务保持不变。
- UI 完成本地化，适应响应式布局，使用主题 token，可用键盘操作，并将无效用户名作为 alert 通知。
- 该占位流程不保护数据，不得将其描述或部署为安全控制。
